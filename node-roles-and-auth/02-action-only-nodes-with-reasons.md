# 02 — Action-Only Nodes & Pipeline Rationale

> A detailed explanation of the 12 nodes that operate strictly as **Actions** with **0 Triggers**, and the structural reasons why they cannot initiate workflows.

---

## 📑 Overview

In **Automate Workflows**, 12 out of 30 nodes are classified as **Action-Only**. These nodes perform data transformation, flow control, external client dispatching, or human interaction.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                         ACTION-ONLY ARCHITECTURE                         │
├──────────────────────┬───────────────────────────────────────────────────┤
│ Category             │ Nodes Included                                    │
├──────────────────────┼───────────────────────────────────────────────────┤
│ 🔀 Flow Control      │ Filter, Router, Delay, Iterator / Loop            │
├──────────────────────┼───────────────────────────────────────────────────┤
│ 📐 Data Formatters   │ Text Formatter, DateTime Formatter, Number Formatter│
├──────────────────────┼───────────────────────────────────────────────────┤

│                      │ API Custom Connector                              │
├──────────────────────┼───────────────────────────────────────────────────┤
│ 👤 Human Interaction │ Human in the Loop (Email Approval / Form Fill)    │
└──────────────────────┴───────────────────────────────────────────────────┘
```

## 1. 🔀 Flow Control Engines: Why They Cannot Be Triggers

### 1.1 Filter (`filter`)
- **What It Does**: Evaluates conditional rules (e.g. `{{step_1.amount}} greater_than 500` AND `{{step_1.country}} equals "US"`). If true, execution continues; if false, the workflow terminates immediately.
- **Why It Cannot Be a Trigger**:
  - A condition requires **subject data** to evaluate. At Step 1, before any external event has fired, no data exists in the pipeline.
  - A filter has no external network listener, no cron timer, and no polling engine. It is a mathematical gatekeeper that only functions when supplied with prior step tokens.

### 1.2 Router (`router`)
- **What It Does**: Splits a workflow into multiple conditional execution branches (Route A, Route B, Route C), each executing distinct action steps.
- **Why It Cannot Be a Trigger**:
  - Like the Filter, a Router relies on evaluating incoming payload properties to determine which branch should run.
  - A workflow topology must begin with a single root event. Branching can only happen *after* the initial event is captured and understood.

### 1.3 Delay (`delay`)
- **What It Does**: Temporarily suspends workflow execution for a specified duration (e.g. `Delay for 3 days`, `Delay until 2026-10-01 09:00:00`, `Rate-limit queue`).
- **Why It Cannot Be a Trigger**:
  - A delay is an operational pause in an **already active** workflow execution lifecycle.
  - If a user wants a workflow to execute at a future date from the start, they use the **Scheduler** node (`scheduler`), not a Delay node. Delay pauses mid-flight data pipelines.

### 1.4 Iterator / Loop & Aggregator (`iterator`)
- **What It Does**: Accepts a JSON array (e.g. `{{step_1.line_items}}` from Shopify or `{{step_1.records}}` from a database) and loops through each element one by one, or aggregates multiple items into a single summary payload.
- **Why It Cannot Be a Trigger**:
  - An iterator requires an **enumerable collection** as an input parameter.
  - Without a prior trigger step retrieving the collection from an external API or database, an iterator has zero items to cycle through.

## 2. 📐 Data Transformation Formatters: Why They Are Action-Only

### 2.1 Text Formatter (`text-formatter`)
- Actions: `split_text`, `change_case`, `find_replace`, `extract_email_url`, `truncate_text`.
- **Reason**: Pure functional string operations. You cannot "trigger" a workflow by splitting a text string that hasn't been received yet.

### 2.2 DateTime Formatter (`datetime-formatter`)
- Actions: `format_date`, `add_subtract_time`, `time_difference`, `current_timestamp`.
- **Reason**: Transforms or shifts timestamp values (e.g. converting `2026-09-10T12:00:00Z` to `YYYY-MM-DD` or converting UTC to IST). It acts on timestamps generated by prior events.

### 2.3 Number Formatter (`number-formatter`)
- Actions: `spreadsheet_formulas`, `math_operation`, `format_currency`, `round_number`, `random_number`.
- **Reason**: Performs arithmetic, currency formatting, or calculates spreadsheet formulas (e.g. `{{step_1.price}} * 1.18`). Requires input values from earlier steps.

## 3. 💻 Execution Engines & Custom Dispatchers

### 3.1 HTTP Request — Send (`http-request`) & API (`api-webhook`)
- **What They Do**: Dispatches custom outbound HTTP requests (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`) or executes GraphQL queries against third-party endpoints.
- **Why They Are Action-Only**:
  - These are **client-side dispatchers**. In the client-server architecture, their job is to make an outbound call across the network.
  - Inbound HTTP listening is handled by the **Webhook — Catch Hook** node (`webhook-catch`).

### 3.2 Code Runner (`code-runner`)
- **What It Does**: Executes arbitrary JavaScript (Node.js) or Python scripts in an isolated, sandboxed WebAssembly / microVM container.
- **Why It Is Action-Only**:
  - The script executes against context inputs (`inputData = { order_id: {{step_1.id}} }`).
  - While scheduled code execution is possible, it is achieved by starting with a **Scheduler** trigger and placing Code Runner as Step 2.

### 3.3 Lookup Table (`lookup-table`)
- **What It Does**: Maps key-value pairs (e.g. converting country codes `"US"` → `"United States"`, or category names `"TECH"` → `"Department 401"`).
- **Why It Is Action-Only**: Static dictionary lookups require a dynamic key token from an earlier step to look up a corresponding value.

---

## 4. 👤 Human in the Loop (`human-approval`)

### Why It Operates Strictly as an Action
- **What It Does**:
  - `wait_for_approval`: Sends an email with interactive Approve/Reject buttons and suspends execution until a human clicks a decision button.
  - `request_user_input`: Generates an interactive form and pauses execution until a team member manually fills in required fields.
- **Why It Cannot Be a Trigger**:
  - Human-in-the-loop workflows always begin with an **originating machine event** (e.g. *New High-Value Lead on HubSpot*, *Refund Request on Shopify*, *Contract Uploaded on Drive*).
  - The workflow starts automatically, processes initial data, and then reaches the Human in the Loop action where execution is paused awaiting human intervention.
  - If a human wants to initiate a workflow directly by filling out a form from scratch, they use an intake trigger like **Automate Forms** or **Google Forms**.

## 🏁 Summary Table

| Action-Only Node | Primary Function | Why Trigger Mode is Structurally Impossible |
|:---|:---|:---|
| **Filter** | Conditional termination gate | Requires preexisting variables to evaluate boolean logic. |
| **Router** | Multi-branch pathway splitter | Branching can only happen after an initial root event exists. |
| **Delay** | Mid-execution timeline pause | Pauses active pipelines; start-of-workflow delays are handled by Scheduler. |
| **Iterator** | Array iteration & item aggregation | Requires an incoming array payload to iterate over. |
| **Text Formatter** | String transformation & extraction | Pure functional operation requiring an input string token. |
| **DateTime Formatter** | Timezone / format conversion | Operates on event timestamps produced by earlier nodes. |
| **Number Formatter** | Math operations & currency formatting | Performs calculations on incoming numeric tokens. |
| **HTTP Request — Send** | Outbound client HTTP dispatcher | Inbound HTTP listening is handled by Webhook Catch Hook. |
| **API Connector** | Custom REST / GraphQL client | Outbound query dispatcher requiring endpoint and token params. |
| **Code Runner** | Sandboxed JS/Python execution | Executes script logic against input parameters from previous steps. |
| **Lookup Table** | Key-value dictionary translation | Requires an incoming key variable to resolve its target value. |
| **Human in the Loop** | Mid-workflow approval / form pause | Pauses an already running workflow for human verification. |
